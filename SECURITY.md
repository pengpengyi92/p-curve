# Security and sensitive information

P-Curve is experimental research software, not a trading, investment-advice or
production-pricing service. Numerical correctness reports are welcome, but a
passing test does not establish suitability for a financial decision.

## Reporting a vulnerability

For a security vulnerability or accidental disclosure, use GitHub's **Report a
vulnerability** private reporting option if it is enabled. Do not place exploit
details, credentials, private source, personal information or proprietary data in
a public issue or pull request.

If private reporting is not available, open a **metadata-only** issue asking the
maintainer for a private reporting channel. Include no payload or sensitive
details. This repository does not promise a response deadline or a supported
production release window.

For a non-sensitive numerical bug, use the reproducible bug report template with
small synthetic inputs. Explain units, conventions, expected behavior and scope;
do not attach real positions or licensed raw data to demonstrate a problem.

## Accidental sensitive submissions

If you have exposed a credential, revoke or rotate it immediately through its
provider; deleting a file or comment does not make the credential safe again.
Notify the maintainer privately where possible. Do not copy the exposed material
into another issue, quote, log or test fixture.

Private PFICC repositories, strategies, raw data, client/employer information and
Git history are outside this repository's public contribution boundary.
